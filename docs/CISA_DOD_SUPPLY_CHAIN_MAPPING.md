# CISA, NIST, DoD, and CMMC Readiness Mapping

MSAA integrity signing evidence is mapped to secure software and supply-chain readiness support. It is not a certification claim.

Readiness support areas:

- NIST SSDF / SP 800-218: protect software from unauthorized modification, verify release integrity, keep build/release evidence, and retain provenance metadata.
- CISA Secure by Design and supply-chain guidance: secure development process evidence, release artifact integrity, supply-chain transparency, and reduced unauthorized modification risk.
- DoD / CMMC readiness: Configuration Management support, System and Information Integrity support, Audit and Accountability support, Incident Response evidence support, and FCI/CUI safeguarding context.

Reports should include:

- canonical manifest path and SHA-256
- signature bundle path
- trusted developer-machine signature status
- developer-machine public key fingerprint
- manifest hash and source file match status
- signer developer identities
- Codex provenance metadata status
- generated artifact exclusions
- limitations and no-endorsement statement

Use terms such as “mapped to,” “readiness support,” and “evidence support.” Do not claim CISA approval, DoD approval, CMMC certification, NIST compliance, or government approval.

MSAA provides local integrity, signing, and readiness evidence. This does not imply CISA, DoD, NIST, CMMC, Yubico, OpenAI, or government approval, certification, or endorsement.
