# Alert Delivery and Persistence

Notification requested is not equivalent to analyst delivery. MSAA records persistence, UI rendering, native request, native failure, view, acknowledgment, escalation, and restoration independently.

Informational alerts may collapse; Low alerts remain queued; Medium alerts require viewing or acknowledgment; High and Critical alerts require explicit acknowledgment. Display, card closure, application restart, grouping, and native suppression do not acknowledge or delete evidence.

The durable controller restores every unacknowledged record. Repeated events may share presentation but must retain occurrence count and first/last times. A Qt adapter must create and mutate widgets only on the GUI thread and keep strong references. The production stack must use each screen's available geometry, stack upward, and summarize only lower-severity overflow.

UserNotifications integration must use privacy-safe lock-screen content and report authorization or bridge failure. Focus modes and organizational policy can suppress presentation, so delivery is never described as guaranteed.
