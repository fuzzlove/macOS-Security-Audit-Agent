# MSAA Resilient Alert Pipeline architecture

Internal detectors submit through the shared `AuditDatabase.record_monitor_event` boundary. It converts each legacy monitor event into a bounded, redacted, versioned `SecurityEvent`. One SQLite `BEGIN IMMEDIATE` transaction appends the receipt ledger, updates one aggregate, records the notification or suppression decision, queues required notification work, increments bounded metrics, updates any compaction record, and appends a chained administrative audit record. The existing `background_monitor_events` table remains a compatibility transport for the per-user notifier; it is not a competing detector pipeline. Notifications are downstream of durable acceptance.

Notifications are downstream of durable acceptance. SQLite uses WAL, parameterized values, a process-wide re-entrant connection lock, and explicit queue limits. Fingerprints use canonical JSON and SHA-256 with detector contracts. Integrity records use keyed HMAC-SHA-256 chains. The current local key file is created with mode 0600 beside the database; a system deployment should replace this boundary with the authorized privileged Keychain/helper integration. This is tamper evidence rather than non-repudiation.

Priority is P0 protected control-plane events, P1 critical, P2 high, P3 medium, and P4 low/informational. Notification selection reserves capacity for P0/P1. Aggregate cardinality and source-rate windows are bounded; excess low-priority identities enter source/rule/priority overflow buckets and produce audit/health evidence. A source-rate anomaly creates one protected `ALERT_FLOOD_DETECTED` receipt per monotonic window without recursively evaluating itself.

Exact duplicates keep the first raw event and newest raw event. Initial-policy, threshold, material-change, escalation, reopened, and protected records remain raw. Intermediate duplicate bodies may be compacted, but sequence, source, priority, disposition, event digest, chain position, aggregate count, and an explicit compaction digest remain.

If SQLite raises an operational/storage error, the caller receives a degraded decision rather than an exception. A bounded emergency deque and mode-0600 size-bounded local fallback journal retain sanitized receipt digests. This fallback is deliberately not represented as equivalent to the authoritative database, and GUI/CLI health reports expose it.
