# Performance benchmark report

Run `python3 scripts/benchmark_alert_pipeline.py --events 10000 --output benchmark.json` on the deployment class. The tool records OS/Python, configured queue/cardinality bounds, duplicate throughput, P50/P95/P99 transaction latency, protected critical insertion latency after the load, process CPU time, maximum resident-set platform metric, database growth, pending notifications, and restart recovery time/count. Results are environment-specific and are not product guarantees. Record hardware, filesystem, FileVault state, power mode, other workload, database location, and configuration alongside review evidence.

Development measurement on 2026-07-18: macOS 26.5.2 x86_64, Python 3.13.14, 10,000 identical low events plus one protected critical insertion. Observed duplicate throughput was 1,042.64 events/second; P50/P95/P99 were 0.831/1.140/5.283 ms; critical insertion was accepted and notification-eligible in 0.713 ms; process CPU time was 9.103 seconds; database growth was 16,285,696 bytes (1,628.4 bytes/receipt); restart recovery was 12.195 ms with 10,001 occurrences recovered. Maximum resident-set output was 38,068,224 platform units. Six durable notification entries remained. This is evidence from one development run, not a deployment capacity claim.

The tool does not yet measure multi-process producer saturation, battery/energy impact, central-node workloads, or network notification delivery. Production sizing requires representative detectors, storage media, retention policy, FileVault state, and sustained/burst workloads.
