# Anti-Ransomware Protection Is Running in Degraded Observation Mode

## Current State

MSAA Anti-Ransomware is running in observation-only mode. The Endpoint Security sensor is unavailable. MSAA may detect synthetic or application-level filesystem activity, but it cannot provide complete process attribution or preemptive containment.

## Detected Conditions

- Endpoint Security sensor installed: No
- Endpoint Security connection active: No
- Endpoint Security entitlement present: No
- Full Disk Access present: No
- Process containment available: No
- Active mode: Observe
- Sensor mode: Degraded observation only

## Security Impact

- Filesystem changes may not be reliably attributed to the responsible process.
- Process signing identity and Team Identifier may be unavailable.
- Preemptive suspension or termination is unavailable.
- Ransomware-like behavior may be detected only after observable file changes.
- Privacy-restricted paths may be invisible without Full Disk Access.
- Synthetic tests do not prove the production Endpoint Security path works.

## Likely Causes

1. The native sensor is not installed.
2. The signed component lacks the Apple-authorized Endpoint Security entitlement.
3. Its signature or provisioning profile does not authorize that entitlement.
4. Endpoint Security client initialization failed.
5. Full Disk Access is not approved.
6. System-extension approval is pending.
7. The sensor was disabled, removed, rejected, or terminated.
8. MSAA is running from source without its production sensor.
9. A development Python runtime cannot host the production integration.
10. GUI, engine, sensor, or protocol build versions do not match.

## Development Environment

1. Confirm development observation mode is intentional.
2. Verify test incidents are visibly marked synthetic.
3. Confirm the UI does not describe synthetic detection as Endpoint Security protection.
4. Review logs for the original native initialization result.
5. Verify IPC/XPC endpoints and protocol versions.
6. Confirm the expected development feature flag is enabled.
7. Treat this mode as algorithm and integration testing, not production protection.

## Signed Production Build

1. Verify each component with `codesign --verify --strict --verbose=4 <component>`.
2. Inspect Team Identifier, signing identifier, CDHash, and designated requirement with `codesign -d --verbose=4 <component>`.
3. Inspect signed entitlements with `codesign -d --entitlements :- <sensor>`.
4. Confirm the provisioning profile authorizes `com.apple.developer.endpoint-security.client`.
5. Confirm the sensor or system extension is installed, activated, and approved by macOS.
6. Grant Full Disk Access to the exact signed component, locally or through approved MDM/PPPC policy.
7. Restart or reconnect the sensor after approval, then run `msaa anti-ransomware status --json`.
8. Require a current live fixture event before accepting Endpoint Security observation readiness.
9. Require the real authenticated helper, identity validation, lease watchdog, and live fixture tests before `containment_available` becomes true.

Apple controls production Endpoint Security entitlement approval. Local signing, pip, root execution, and editing an entitlement plist cannot grant that approval.

- View Sensor Diagnostic Logs — inspect the native result without exposing secrets.

- Export Diagnostic Report — preserve build-bound evidence for the release engineer.
